Overview

This project implements a real-time pixelation effect using Vulkan compute shaders. The effect is applied to a rendered image by sampling and writing back to a storage image, with correct synchronisation between compute and graphics pipelines.

Technical Breakdown

The pixelation effect is driven by a compute shader that operates on a storage image. A pixel size parameter controls how aggressively the image is downsampled visually, and is animated over time via push constants or uniform updates in the main loop. 


// Fragment of a compute shader for pixelation
layout(local_size_x = 8, local_size_y = 8) in;

layout(binding = 0, rgba8) uniform readonly image2D inputImage;
layout(binding = 1, rgba8) uniform writeonly image2D outputImage;

layout(push_constant) uniform PushConstants {
    float pixelSize;
} pc;

void main() {
    ivec2 coord = ivec2(gl_GlobalInvocationID.xy);
    ivec2 base = ivec2(coord / int(pc.pixelSize)) * int(pc.pixelSize);
    vec4 color = imageLoad(inputImage, base);
    imageStore(outputImage, coord, color);
}

Synchronisation & Layouts

The project focuses on correct image layout transitions and pipeline barriers between compute and graphics queues. The rendered image is transitioned to a layout suitable for compute access, processed, then transitioned back for presentation in the graphics pipeline.

Challenges & Solutions

  • Validation errors due to incorrect image layouts → resolved with explicit layout transitions.
  • Race conditions between compute and graphics → fixed using appropriate pipeline barriers.
  • Performance tuning of workgroup sizes → adjusted to balance GPU utilisation and overhead.

Reflection

Future work could extend the effect into a full post-processing stack, add user-controlled parameters, and integrate more advanced temporal behaviour such as animated transitions or blending with other visual effects.
